Testing the assistant on your computer

Reviews happen here, on your own machine, so nothing is deployed to Vercel for each change. Steps are for a Mac; Windows differences are noted.

Once: sections 1 to 4 (about 20 minutes).
Every review after that: section 5 only (two clicks and one command).

1. Install three free apps

  1. Node.js 22 (runs the code): download the “22 LTS” installer from nodejs.org and run it.
  2. Postgres.app (the database, on your computer only): download from postgresapp.com, drag it to Applications, open it and click Initialize. It stays running in the menu bar.
    Windows: install PostgreSQL 16 from postgresql.org and remember the password you choose.
  3. GitHub Desktop (gets the code and updates it): desktop.github.com. Sign in with your GitHub account.

Then open the Terminal app (press ⌘ Space, type “Terminal”) and run this once. It turns on pnpm, the tool that installs the project’s parts. It asks for your Mac password; nothing shows while you type it. 

sudo corepack enable pnpm

2. Make the database

In Postgres.app, double-click the database named postgres. A Terminal window opens. Type this and press Return, then close that window: 

CREATE DATABASE ai_assistant;

3. Get the code

  1. In GitHub Desktop: File → Clone Repository, pick Andrewoh2020/AI-assistant, keep the suggested folder, click Clone.
  2. At the top, click Current Branch and choose the branch of the pull request you are reviewing (for the first one: claude/initial-build-1ovsu4).
  3. Choose Repository → Open in Terminal. Run the remaining commands in that window.

4. Add your settings

This makes a private settings file (it is never uploaded to GitHub) and opens it:

cp .env.example .env
open -e .env

Fill in these lines, save, and close TextEdit:

Line What to put
DATABASE_URL postgres://localhost:5432/ai_assistant
Windows: postgres://postgres:YOUR-PASSWORD@localhost:5432/ai_assistant
TRAVILA_API_KEY Your Travila secret key (from the Travila dashboard).
DEEPSEEK_API_KEY Your DeepSeek key (from platform.deepseek.com).
SIGNUP_CODE Any word you like. You type it once to create your account.

Leave everything else empty. SESSION_SECRET is only needed on the hosted site.

5. Start it (every review)

  1. In GitHub Desktop, pick the review’s branch under Current Branch, then click Fetch origin and Pull origin if it offers.
  2. In the Terminal window, run:
pnpm install
pnpm local

The very first time, it may ask to download pnpm. Type Y and press Return.

pnpm local builds everything, updates your database to the newest design, and starts the site. When you see Ready, open http://localhost:3000. The first time, choose Create an account and use your SIGNUP_CODE.

To stop it, click the Terminal window and press Control C. Your chats stay in your local database for next time.

What to try for the first review

  • Ask something recent, like “Who won the 2026 World Cup final?”
  • While it works you see what it is doing (“Searching…”, “Reading 3 pages…”) and a Stop button.
  • The answer has small numbered chips. Clicking one highlights that source on the right; each source opens the real page.
  • “How I worked this out” folds out the assistant’s reasoning.
  • Start a New side chat, switch your Mac to dark mode, and make the window narrow like a phone.

If something goes wrong

You see Do this
command not found: pnpm Run sudo corepack enable pnpm again, then open a new Terminal window.
ECONNREFUSED or “database does not exist” Open Postgres.app (it must be running) and redo section 2.
Port 3000 is in use Another copy is still running. Close the old Terminal window and try again.
“That invite code isn’t right.” Check SIGNUP_CODE in .env, then stop and start again.
A question ends with “Failed” Usually a key. Check TRAVILA_API_KEY and DEEPSEEK_API_KEY in .env; the Terminal window shows the exact error.

The hosted site, for later

A Vercel project (ai-assistant) and its own Neon database exist, separate from your other apps. Pushing to GitHub does not deploy it, so it costs nothing until we decide to deploy. The first deploy sets up its database on its own. Your local database and the hosted one never share data.
